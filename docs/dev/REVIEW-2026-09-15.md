## Method

- Read all of `reformat-core/src`, `reformat-cli/src`, `reformat-plugins/src`, `README.md`, `TODO.md` and the CI workflow.

- Ran `make test`: 264 tests, all pass.

- Probed the debug binary in a scratch directory. Every behaviour marked **[verified]** below was reproduced. Items marked **[inference]** rest on reading the code or on judgement, not on a run.

## Summary

The core is careful. Line terminators survive edits (`lines.rs`), binary and non-UTF-8 files are skipped (`text.rs`), and `.git` is pruned during the walk (`walk.rs`). The gaps are in the layer around the transformers:

1. **No CI or pre-commit mode.** A dry run exits 0 even when changes are pending. The CLI takes one path, so a hook cannot pass it a file list.

2. **No diff preview.** A dry run reports counts ("Would clean 1 lines"), not the changes themselves. Review before applying is the documented safety model, and it has no tool support.

3. **File selection is fixed.** It ignores `.gitignore`, always skips hidden directories (`.github/`), never matches extensionless files (`Makefile`), and `--glob` exists only on `convert`.

4. **The preset schema allows one config per step type.** A single preset cannot insert `//` headers in `.rs` and `#` headers in `.py`.

5. **No string-level library API.** Every transformer takes a path. Editors, stdin filters and plugins need `&str -> String`.

Fix the defects in section 1 first. Several of them block section 2 features.

## 1. Defects found while probing

These are bugs, not missing features. They are listed because several features below depend on them being fixed.

| # | Defect | Evidence |
|-|-|-|
| D1 | The default command lowercases every file name regardless of type. `reformat -r .` in a Rust project renames `Cargo.toml` to `cargo.toml` and `Makefile` to `makefile`, which breaks the build. | [verified]. `FileRenamer::should_process` (`rename.rs:123`) has no extension filter. `CombinedProcessor` applies it to all files (`combined.rs:123`). |
| D2 | `recursive` cannot be turned off on `clean`, `emojis`, `rename_files`, `endings`, `indent`, `replace` or `header`. `--recursive=false` is rejected. | [verified]. `#[arg(short = 'r', long, default_value_t = true)] recursive: bool` (`main.rs:203` and others) is a `SetTrue` flag with a true default. |
| D3 | `emojis --replace-task` and `--remove-other` cannot be disabled. The README example `reformat emojis --replace-task --no-remove-other` fails with "unexpected argument". | [verified]. Same pattern, `main.rs:233`, `main.rs:237`. |
| D4 | `-e py` (no leading dot) matches nothing, silently, and exits 0. | [verified]. Extension check compares against `format!(".{}", ext)` (`whitespace.rs:71` and copies). |
| D5 | `convert` logs per-file errors, prints "Conversion complete" and exits 0. `clean` aborts the walk on the first I/O error. Error policy differs per transformer. | [verified]. `converter.rs:291` warns and continues. Other transformers propagate with `?`. |
| D6 | `header` inserts the header before a UTF-8 BOM, which moves the BOM mid-file. In a CRLF file it inserts LF separators, so the file ends up with mixed line endings. | [verified]. Output bytes: `// Copyright 2026 X \n \n 357 273 277 int x; \r \n`. `header.rs:184-188` uses a literal `"\n\n"` and does not skip the BOM. |
| D7 | A `group` step inside a preset or job discards its `ChangeRecord`. No `changes.json` is written, so reference fixing is impossible from a pipeline. | [verified]. `main.rs:1273-1277` keeps only `.stats`. |
| D8 | `group` prints "You can review fixes.json and apply them later" (`main.rs:1008`). No command exists to do that. | [verified] by reading the `Commands` enum. |
| D9 | README says "`--extensions` and `--glob` limit the blast radius". `--glob` exists only on `convert`. | [verified]. `reformat clean --glob` fails. |
| D10 | `group --preview -r` ignores `-r`. | [verified]. `preview` calls `analyze_directory` on the root only (`group.rs:347`). |
| D11 | Writes are not atomic. A crash or full disk during `fs::write` truncates the file. The tool has no undo, so the content is lost. | [inference]. `fs::write` truncates, then writes. The fix is write-to-temp plus `rename`, copying permissions first. |

## 2. Missing features, ranked

Ranking criterion: developer value divided by implementation cost, given what the codebase already has.

### Tier 1: CI and workflow integration

These decide whether `reformat` can run unattended. Today it cannot gate anything.

**F1. `--check` mode.** Exit non-zero when any file would change, and write nothing. This is the contract of `rustfmt --check`, `black --check` and `prettier --check`. The dry-run path already computes whether each file changes. The missing piece is an aggregate "changed" bit and an exit code. [verified: dry run exits 0 with pending changes.]

**F2. `--diff` output.** Print a unified diff per file in dry-run and check modes. The `similar` crate ([docs.rs/similar](https://docs.rs/similar)) produces unified diffs. For `rename_files` and `group`, print `old -> new` pairs, which the tool already logs. Without this, reviewing a whole-tree `convert` means running it and then reading `git diff`. That works only inside a clean git tree.

**F3. Multiple paths and file lists.** Accept `PATH...` instead of one `PATH`. pre-commit ([pre-commit.com](https://pre-commit.com/#new-hooks)) and `lint-staged` pass
staged file names as arguments. `git diff --name-only | xargs reformat clean`
also needs this. [verified: `reformat clean a.py b.py` fails with "unexpected argument".] A `--files-from -` option covers lists too long for argv.

**F4. `.pre-commit-hooks.yaml`.** Publish hook definitions (`reformat-clean`, `reformat-endings`, and so on). This costs one YAML file once F1 and F3 exist. It puts the tool in front of every team that already uses pre-commit.

**F5. Git-dirty guard.** Before a destructive run (rename, group, convert, replace), refuse when the target is inside a git work tree with uncommitted changes, unless the user passes `--allow-dirty`. `cargo fix` does exactly this ([cargo fix docs](https://doc.rust-lang.org/cargo/commands/cargo-fix.html)). It enforces the README's own first rule ("Run against a clean working tree"). Shelling out to `git status --porcelain` is enough; no libgit2 dependency is needed.

### Tier 2: File selection

**F6. Replace `walkdir` plus `DEFAULT_SKIP_DIRS` with the `ignore` crate.** `ignore::WalkBuilder` ([docs.rs/ignore](https://docs.rs/ignore)) is ripgrep's walker. It provides:

- `.gitignore`, `.ignore` and global git excludes.

- A hidden-file toggle, so `.github/workflows/*.yml` becomes reachable. [verified: skipped today, `walk.rs:87`.]

- Glob overrides, which give `--include` and `--exclude` on every subcommand. This also closes D9.

- A parallel walker, if throughput ever matters.

The hardcoded list (`walk.rs:72`) also skips legitimate source directories named `build`, `dist` or `vendor`, with no opt-out. Keep `.git` as a hard refusal. Make the rest defaults the user can override.

**F7. Normalised extension matching and extensionless files.** Accept `py`, `.py` and `.PY` as the same extension (closes D4). Add a `--name` or glob match for `Makefile`, `Dockerfile`, `LICENSE` and `CODEOWNERS`, which no transformer can reach today. [verified: `Makefile` with trailing whitespace is not cleaned.]

**F8. Deduplicate `should_process`.** Seven transformers carry near-identical copies (`whitespace.rs:55`, `endings.rs:87`, `indent.rs:80`, `replace.rs:78`, `header.rs:101`, `emoji.rs:122`, and the variant in `converter.rs:211`). This is a prerequisite for F6 and F7 rather than a feature. Without it, each selection feature has to be implemented seven times.

### Tier 3: Transformer gaps

**F9. End-of-file hygiene in `clean`.** Add `insert_final_newline`, `trim_trailing_blank_lines` and `strip_bom`. These are the pre-commit-hooks `end-of-file-fixer` and `fix-byte-order-marker` hooks ([pre-commit-hooks](https://github.com/pre-commit/pre-commit-hooks)). Their absence is the most likely reason a team keeps a second tool. [verified: `a\n\n\n` and a file without a final newline both report "No files needed cleaning".]

**F10. EditorConfig support.** Read `.editorconfig` ([spec](https://spec.editorconfig.org/)) and derive per-file options:

| EditorConfig key | Transformer option |
|-|-|
| `indent_style`, `indent_size`, `tab_width` | `indent.style`, `indent.width` |
| `end_of_line` | `endings.style` |
| `trim_trailing_whitespace` | `clean.remove_trailing` |
| `insert_final_newline` | F9 |
| `charset = utf-8` | F9 `strip_bom` |

Many repositories already declare their style this way. With F10, `reformat` needs no config for them and cannot contradict the editor. An EditorConfig parser crate exists (`ec4rs`), but check its maintenance status before adopting it. [inference]

**F11. `replace` parity with `sd`.** Compared with [`sd`](https://github.com/chmln/sd), `replace` lacks:

- Repeated `--find`/`--replace-with` pairs on the CLI. [verified: rejected.]

- `--literal` (fixed string). Today users must `regex::escape` by hand.

- `--ignore-case`. `(?i)` works but is undocumented.

- A per-pattern extension scope.

- A match count or preview per pattern.

**F12. `header` per-language comment syntax.** The header text embeds its comment markers, so one config serves one comment syntax. Proposal: `text` holds the body only, and a built-in table maps extension to comment style (`//`, `#`, `/* */`, `<!-- -->`). Google's [`addlicense`](https://github.com/google/addlicense) works this way and also provides `-check`, which is the license-compliance form of F1. Also missing: removing or replacing a header that does not match the template, such as a different organisation name.

**F13. `rename_files` gaps.**

- A `ChangeRecord` for renames, fed to the existing `ReferenceScanner`. Renaming `userList.tmpl` breaks every reference to it, and `refs.rs` already solves that problem for `group`. This is the highest-value item in this group because it reuses existing code.

- Directory renaming. Only files are walked today (`walk.rs:143`).

- Regex rename (`s/pat/repl/`), as in [`rnr`](https://github.com/ismaelgv/rnr) or `f2`.

- A case-collision check (`Foo.txt` and `foo.txt` in one directory). On macOS and Windows these collide. pre-commit-hooks ships `check-case-conflict` for this.

- A protected-names list (`Cargo.toml`, `Makefile`, `README*`, `LICENSE*`). This is the minimum fix for D1.

**F14. Standalone reference commands.** `reformat refs scan --changes changes.json --scope src` and `reformat refs apply fixes.json`. The library functions exist (`ReferenceScanner::scan`, `ReferenceFixer::apply_fixes`). Only the CLI entry points are missing. This closes D8 and makes the non-interactive path usable.

**F15. `reformat undo changes.json`.** `group` records every move with relative paths. Reversing the list is cheap. Content transformers have no record. F5 (git guard) is the better answer for those than a backup system.

**F16. Unicode typography normalisation.** [inference on audience] The emoji transformer and its task-marker table suggest the tool targets generated or pasted prose. The same text commonly carries curly quotes, en and em dashes, non-breaking spaces (U+00A0), zero-width spaces (U+200B) and the ellipsis character (U+2026). An ASCII-normalisation step belongs next to `emojis`. If the audience is source code only, skip this.

### Tier 4: Pipelines and configuration

**F17. Step instances in the preset schema.** `Preset` has one optional field per step type (`config.rs:347`). A second `"header"` in `steps` reruns the same config. [verified.] Proposed schema:

```json
{
  "steps": [
    { "use": "header", "extensions": [".rs", ".go"], "text": "// Copyright {year} X" },
    { "use": "header", "extensions": [".py"], "text": "# Copyright {year} X" },
    { "use": "replace", "patterns": [{ "find": "old_api\\(", "replace": "new_api(" }] }
  ]
}
```

Accept the current shape as well, so existing `reformat.json` files still load. `deny_unknown_fields` already gives good errors, and the per-step `*Config` structs carry over unchanged.

**F18. Pipeline-level defaults.** Put `include`, `exclude`, `extensions` and `recursive` at the preset level, inherited by each step. Today every step repeats `file_extensions`.

**F19. Single-pass, in-memory pipeline.** Each step now walks the tree and reads and writes every file itself, so N content steps cost N reads and N writes per file. Reading once, applying the content steps in order and writing once gives:

- One write per file, which makes the D11 atomic-write fix cheaper.

- An accurate multi-step dry run. Today step 2 of a dry run reads content that step 1 never wrote, so its report describes the wrong input.

- One diff per file for F2, instead of one diff per step.

This needs F22 (a string-level API). Rename and group stay as separate passes, because they change paths rather than content.

**F20. Config discovery and tooling.**

- `--config <path>`.

- Search for `reformat.json` from the target path as well as the cwd. [verified: `reformat -p x p2/` fails when `p2/reformat.json` exists and the cwd is outside `p2`.]

- `reformat presets` to list the presets and their steps.

- `reformat config validate`.

- A published JSON Schema, for editor completion.

- The `default` preset from `TODO.md`.

- A format that allows comments (JSONC or TOML). Regex-heavy presets need comments to be maintainable.

**F21. Shell completions and man page.** `clap_complete` and `clap_mangen` generate both from the existing `clap` definitions. The cost is a small `build.rs` or a hidden subcommand.

### Tier 5: Library and integration API

**F22. A `Transformer` trait with a string-level method.**

```rust
pub trait ContentTransform {
    fn name(&self) -> &str;
    /// Returns None when the input is unchanged.
    fn apply(&self, text: &str, path: &Path) -> Result<Option<(String, usize)>>;
}
```

Today every public method takes a path: `clean_file`, `transform_file`, `replace_file`. `CaseConverter::convert` is private. The trait enables F19, stdin mode (F23), editor integration and `reformat-plugins`. The plugins crate is an empty struct today (`reformat-plugins/src/lib.rs`). Recommendation: ship the trait and leave dynamic loading out. Rust has no stable ABI, so a real plugin loader means WASM or a subprocess protocol, and no user has asked for either. [inference]

**F23. stdin/stdout filter mode.** `reformat clean --stdin-filename foo.py < in > out` lets editors run it on save without touching disk. [verified: `-` is treated as a file path.] Requires F22.

**F24. Machine-readable output.** `--format json` would emit one record per file (path, step, units changed, skipped reason). `--format github` would emit `::warning file=...,line=...::` annotations for GitHub Actions ([workflow commands](https://docs.github.com/en/actions/writing-workflows/choosing-what-your-workflow-does/workflow-commands-for-github-actions)). The stats structs already exist, but the CLI flattens them into log lines.

**F25. `CaseConverter` builder.** `CaseConverter::new` takes 15 positional arguments (`converter.rs:64`), 11 of them `Option<String>` or `String`. A transposed `strip_prefix` and `strip_suffix` compiles silently. Give it an options struct with `Default`, like every other transformer. This is an API break, so do it before 1.0.

### Not recommended now

- **Parallelism (`rayon`).** There is no benchmark showing I/O or regex time is a bottleneck. F6 provides a parallel walker if one appears. One real cost exists: `CombinedProcessor` compiles the emoji regexes once per file (`combined.rs:147`). Hoist that first.

- **Syntax-aware `convert`.** Tree-sitter per language is a large dependency and maintenance commitment. Point users to [`ast-grep`](https://ast-grep.github.io/) or [`comby`](https://comby.dev/) for structural rewrites. A cheaper middle ground is an explicit identifier map (`--map oldName=new_name`), which avoids shape-based matching of prose.

## 3. Alternative framings

The feature list above assumes one product. The code supports two, and they set different priorities.

**Framing A: a hygiene checker.** It runs on every commit and in CI, and is mostly read-only. The core steps are `clean`, `endings`, `indent`, `header` and `emojis`. Priorities: F1, F3, F4, F6, F9, F10, F24. `convert`, `group` and `rename_files` are out of scope or opt-in.

**Framing B: a migration tool.** It runs once, rewrites a tree, and a human reviews the result. The core steps are `rename_files`, `group`, `convert`, `replace` and reference fixing. Priorities: F2, F5, F13, F14, F15, F17, and structural matching.

The default command (`reformat <path>`: lowercase rename, emojis, clean) mixes the two. It is presented as routine cleanup, yet it performs an irreversible rename that breaks builds (D1). Recommendation: make the default command content-only (framing A), and require an explicit subcommand or preset for renames.

## 4. Open questions

1. **Who is the primary user?** Default extensions include `.qmd`, `.md` and `.txt`, and the task-emoji mapping suggests notes and docs repos. If so, F16 rises and F25 falls.

2. **Is git a safe assumption?** F5 and a `--staged` option assume a git work tree. Non-git users need the atomic-write and backup path (D11) instead.

3. **What should `reformat-plugins` become?** If the answer is "a trait for library users", merge it into `reformat-core` and drop the crate. If it means runtime loading, pick WASM or a subprocess protocol before writing any API.

4. **Should the tool fail on the first error or collect errors?** `rename_files` collects, `convert` swallows and the rest abort (D5). A single policy (collect, report, exit non-zero) is needed before F1 and F24 can report reliably.

5. **Is JSON-only config deliberate?** It blocks comments in regex-heavy presets (F20).

## 5. Suggested sequence

| Phase | Items | Why this order |
|-|-|-|
| 0 | D1-D11 | Correctness. D2, D3 and D9 are also documentation-visible. |
| 1 | F8, F6, F7, F3 | Shared file-selection layer. Every later feature uses it. |
| 2 | F22, F19, F1, F2 | String API, then single-pass pipeline, then check and diff built on it. |
| 3 | F4, F5, F9, F10 | Adoption: pre-commit, safety guard, EditorConfig. |
| 4 | F13, F14, F15 | Migration support reusing `refs.rs` and `changes.rs`. |
